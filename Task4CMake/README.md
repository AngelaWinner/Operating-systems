# Лабораторная работа №4: Межпроцессное взаимодействие с использованием CMake

## Описание проекта

Проект реализует систему межпроцессного взаимодействия (IPC) на платформе Windows с использованием C++ и системы сборки CMake. Система обеспечивает передачу сообщений между одним процессом Receiver и несколькими процессами Sender через общий бинарный файл, организованный как кольцевая очередь FIFO.

## Конфигурация CMake

### CMakeLists.txt содержит:
- Минимальная версия CMake: 4.0
- Стандарт C++: C++23
- Три исполняемых файла: Receiver, Sender, Tests
- Автоматическая загрузка Google Test через FetchContent
- Интеграция тестирования с `enable_testing()` и `gtest_discover_tests()`

### Сборка проекта:
```bash
# Создание директории сборки
mkdir build
cd build

# Генерация файлов сборки
cmake ..

# Компиляция всех целей
cmake --build .

## Задание лабораторной работы

### Цель
Изучение механизмов синхронизации процессов и организации межпроцессного взаимодействия через разделяемые ресурсы с использованием файловой системы.

### Основные компоненты:

**Процесс Receiver (Receiver.cpp):**
- Ввод параметров: имя файла, размер очереди, количество отправителей
- Создание и управление бинарным файлом-очередью
- Инициализация объектов синхронизации Windows (мьютексы, семафоры, события)
- Автоматический запуск процессов Sender
- Чтение сообщений из кольцевой очереди

**Процесс Sender (Sender.cpp):**
- Получение параметров через командную строку
- Подключение к существующей системе синхронизации
- Запись сообщений в очередь с соблюдением синхронизации
- Взаимодействие с пользователем через консоль

## Механизмы синхронизации

### 1. Файловая система:
- **Бинарный файл сообщений**: Фиксированные блоки по 20 байт
- **Файл позиции записи** (`.pos`): Текущая позиция для записи
- **Файл позиции чтения** (`.readpos`): Текущая позиция для чтения

### 2. Объекты синхронизации Windows:
- **Мьютексы (Mutexes)**:
  - `"MyMutex"` - общий доступ к файлу
  - `"MyPositionMutex"` - синхронизация позиций
- **Семафоры (Semaphores)**:
  - `"MyNotesAmountSemaphore"` - счетчик доступных сообщений
  - `"MyNotNotesAmountSemaphore"` - счетчик свободного места
- **События (Events)**:
  - `"MyStartEventN"` - синхронизация запуска процессов

### 3. Кольцевая очередь FIFO:
- Циклическое использование буфера
- Автоматический возврат к началу при достижении конца
- Гарантия порядка сообщений "первым пришел - первым обслужен"

## Goofle-тестирование

### Устройство тестирования:
- **Google Test Framework**: Автоматически загружается через CMake FetchContent
- **Файл test.cpp**: Содержит 11 тестов для валидации данных
- **Интеграция с CMake**: `gtest_discover_tests()` автоматически регистрирует тесты

### Тестовые группы:
1. **ValidatePositiveNumber**: Проверка корректности положительных чисел
   - Валидные: "1", "10", "100", "999"
   - Невалидные: "0", "-1", "01", "1a", "", " 1"

2. **ValidateFilename**: Проверка допустимых имен файлов
   - Валидные: "test", "test123", "test-file", "test_file"
   - Невалидные: "test file", "test.file", "test@file", "../test"

3. **ValidateChoice**: Проверка пользовательских выборов
   - Валидные: "0", "1"
   - Невалидные: "2", "01", "a", " ", "-1"

4. **EdgeCaseTest**: Граничные случаи
   - Пустые строки
   - Специальные символы

## Особенности реализации

### 1. Валидация данных:
- Все пользовательские входные данные проверяются регулярными выражениями
- Предотвращение некорректного ввода через циклы повторного запроса
- Ясные сообщения об ошибках

### 2. Безопасность ресурсов:
- Корректное освобождение всех HANDLE объектов
- Обработка ошибок Windows API функций
- Гарантированное закрытие файлов

### 3. Синхронизация:
- Строгий порядок захвата ресурсов для предотвращения deadlock
- Использование семафоров для эффективного ожидания
- Раздельные мьютексы для файлов и позиций

### 4. Управление процессами:
- Автоматическое создание консолей для каждого Sender
- Передача параметров через командную строку
- Синхронизация запуска через события
