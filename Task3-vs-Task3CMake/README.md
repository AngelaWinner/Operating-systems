# Лабораторная работа №3: Синхронизация потоков - Две реализации

## Описание проекта

Проект содержит две реализации многопоточного консольного приложения на C++ для изучения механизмов синхронизации потоков. Обе программы реализуют модель управления несколькими рабочими потоками (marker), которые конкурируют за доступ к общему массиву, но используют разные подходы и технологии.

## Реализации

### 1. Task3.cpp - Windows API реализация
**Особенности:**
- Использование чистого Windows API
- Работа с критическими секциями (`CRITICAL_SECTION`) и событиями (`CreateEvent`)
- Использование `CreateThread` для создания потоков
- Более низкоуровневое управление потоками
- Совместимость со стандартом C++98

### 2. Task3CMake.cpp - Modern C++ реализация
**Особенности:**
- Использование стандарта C++20
- Работа с `std::thread`, `std::mutex`, `std::condition_variable`
- Современный подход к многопоточности
- Использование RAII для управления ресурсами
- Интеграция с системой сборки CMake

## Ключевые отличия реализаций

| Аспект | Task3.cpp (Windows API) | Task3CMake.cpp (Modern C++) |
|--------|-------------------------|-----------------------------|
| **Стандарт C++** | C++98 | C++20 |
| **Потоки** | `CreateThread` Windows API | `std::thread` из STL |
| **Синхронизация** | `CRITICAL_SECTION`, `CreateEvent` | `std::mutex`, `std::condition_variable` |
| **Управление памятью** | Ручное (new/delete) | RAII, `std::vector` |
| **Задержки** | `Sleep()` Windows API | `std::this_thread::sleep_for()` |
| **Переносимость** | Только Windows | Кроссплатформенный |
| **Подход к синхронизации** | События Windows | Условные переменные C++ |
| **Сборка** | Простая компиляция | CMake система сборки |

## CMake конфигурация

Файл `CMakeLists.txt` создает две отдельные цели сборки:

### Цель 1: Task3_Cpp98
- Компилирует `Task3.cpp`
- Использует стандарт C++98
- Windows API зависимости

### Цель 2: Task3_Cpp20
- Компилирует `Task3CMake.cpp`
- Использует стандарт C++20
- Только стандартная библиотека C++

## Преимущества CMake версии

1. **Автоматическое управление зависимостями**: CMake находит и подключает необходимые библиотеки
2. **Кроссплатформенность**: Одна конфигурация работает на Windows, Linux, macOS
3. **Управление стандартами**: Разные стандарты C++ для разных целей

## Алгоритм работы (общий для обеих версий)

### Фаза 1: Инициализация
1. Пользователь задает размер массива
2. Массив инициализируется нулями
3. Задается количество потоков marker
4. Создаются потоки с уникальными ID

### Фаза 2: Работа потоков
1. Каждый поток пытается пометить случайные элементы массива
2. При успехе: ставит свой ID, пауза 5 мс
3. При неудаче: сообщает main и ждет команды

### Фаза 3: Управление
1. Когда все потоки заблокированы, выводится состояние массива
2. Пользователь выбирает поток для завершения
3. Выбранный поток обнуляет свои метки и завершается
4. Остальные потоки продолжают работу

### Фаза 4: Завершение
Процесс повторяется до завершения всех потоков

## Сравнение механизмов синхронизации

### Windows API (Task3.cpp):
```
CRITICAL_SECTION cs;  // Критическая секция
HANDLE event;         // Событие
EnterCriticalSection(&cs);  // Вход в критическую секцию
SetEvent(event);            // Установка события
```

### Modern C++ (Task3CMake.cpp):
```
std::mutex mtx;                     // Мьютекс
std::condition_variable cv;         // Условная переменная
std::unique_lock<std::mutex> lock(mtx);  // Блокировка с RAII
cv.notify_one();                    // Уведомление
```

## Особенности каждой реализации

### Task3.cpp (Windows API):
1. **Прямой доступ к ОС**: Минимальные накладные расходы
2. **Тонкий контроль**: Прямое управление дескрипторами потоков и событий
3. **Windows-специфичность**: Использует особенности Windows
4. **Ручное управление памятью**: Требует внимательности при освобождении ресурсов

### Task3CMake.cpp (Modern C++):
1. **Безопасность**: Автоматическое управление ресурсами через RAII
2. **Переносимость**: Код работает на любой платформе с поддержкой C++20
3. **Современный синтаксис**: Использование лямбда-выражений, range-based for
4. **Интеграция с CMake**: Автоматическая настройка сборки

## Вывод

Обе реализации демонстрируют различные подходы к многопоточному программированию. Windows API версия показывает низкоуровневую работу с потоками и синхронизацией, в то время как Modern C++ версия демонстрирует современные, безопасные и переносимые практики программирования. CMake система сборки добавляет профессиональный уровень управления проектом, делая его удобным для разработки и поддержки.
