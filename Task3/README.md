# Лабораторная работа №3: Синхронизация потоков

## Описание проекта

Проект представляет собой многопоточное консольное приложение на C++, демонстрирующее синхронизацию потоков с использованием критических секций и событий. Программа реализует модель "master-worker", где основной поток управляет несколькими рабочими потоками (marker), которые конкурируют за доступ к общему массиву.

## Задание лабораторной работы

### Цель
Изучение механизмов синхронизации потоков в Windows с использованием критических секций и событий, обработка потенциальных тупиковых ситуаций.

### Требования к программе:

1. **Основной поток (main)**:
   - Выделение памяти под массив целых чисел (размер задается пользователем)
   - Инициализация массива нулями
   - Запуск заданного количества потоков marker
   - Ожидание сигналов от всех потоков о невозможности продолжения
   - Интерактивное управление потоками (завершение выбранного потока)
   - Вывод состояния массива на разных этапах

2. **Поток marker**:
   - Запуск по сигналу от main
   - Инициализация генератора случайных чисел с уникальным seed
   - Циклическая попытка пометить случайные элементы массива
   - При обнаружении занятой ячейки - отправка сигнала main
   - Ожидание команд от main (продолжить или завершиться)
   - При завершении - обнуление всех помеченных элементов

## Реализация

### Task3.cpp
**Особенности**:
- Использование стандарта C++ с `std::thread`, `std::mutex`, `std::condition_variable`
- Реализация сложной синхронизации между потоками
- Интерактивное управление потоками в runtime
- Безопасная обработка исключений и освобождение ресурсов

### Вспомогательные функции (Functions.h/Functions.cpp)
- `initializeArray()` - инициализация массива нулями
- `tryMarkElement()` - попытка пометить элемент массива
- `clearMarkedElements()` - очистка помеченных элементов
- `printArray()` - вывод массива на экран
- `readArraySize()` и `readThreadsCount()` - чтение параметров с валидацией

## Механизмы синхронизации

1. **Мьютексы (mutex)**: Для защиты критических секций
2. **Условные переменные (condition_variable)**: Для сигнализации между потоками
3. **Флаги состояний**: Управление жизненным циклом потоков
4. **RAII-обертки**: `std::unique_lock`, `std::lock_guard` для безопасной работы с мьютексами

## Алгоритм работы

1. **Инициализация**: 
   - Пользователь задает размер массива и количество потоков
   - Массив заполняется нулями
   - Создаются потоки marker с уникальными идентификаторами

2. **Рабочая фаза**:
   - Каждый поток пытается пометить случайные элементы массива
   - При успехе - ставит свой идентификатор, пауза 5 мс
   - При неудаче - сообщает main и ждет команды

3. **Управляющая фаза**:
   - Когда все потоки заблокированы, main выводит массив
   - Пользователь выбирает поток для завершения
   - Выбранный поток обнуляет свои метки и завершается
   - Оставшиеся потоки продолжают работу

4. **Завершение**:
   - Процесс повторяется, пока все потоки не будут завершены

## Особенности реализации

1. **Потокобезопасность**: Все операции с общими данными защищены мьютексами
2. **Отсутствие утечек**: Динамически созданные объекты корректно удаляются
3. **Обработка ошибок**: Проверка корректности ввода пользователя
4. **Предсказуемость**: Использование `srand()` с уникальными seed для каждого потока
5. **Интерактивность**: Возможность динамического управления потоками во время выполнения

## Примечания

1. Программа демонстрирует типичные проблемы синхронизации
2. Паузы в 5 мс имитируют вычисления
3. Алгоритм гарантирует, что в конечном итоге все потоки будут завершены
4. Реализация устойчива к некорректному вводу пользователя
