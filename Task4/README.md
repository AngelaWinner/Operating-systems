# Лабораторная работа №4: Межпроцессорное взаимодействие

## Описание проекта

Проект реализует систему межпроцессного взаимодействия (IPC) на платформе Windows с использованием C++. Система обеспечивает передачу сообщений между одним процессом Receiver и несколькими процессами Sender через общий бинарный файл, организованный как кольцевая очередь FIFO (First-In-First-Out).

## Задание лабораторной работы

### Цель
Изучение механизмов синхронизации процессов и организации межпроцессного взаимодействия через разделяемые ресурсы.

### Требования к реализации:

**Процесс Receiver:**
1. Ввод имени бинарного файла и количества записей в очереди
2. Создание бинарного файла для сообщений (макс. длина сообщения - 20 символов)
3. Ввод количества процессов Sender
4. Запуск процессов Sender с передачей имени файла через командную строку
5. Ожидание сигналов готовности от всех процессов Sender
6. Циклическое чтение сообщений из файла или завершение работы

**Процесс Sender:**
1. Открытие файла для передачи сообщений (имя получает из командной строки)
2. Отправка сигнала готовности процессу Receiver
3. Циклическая отправка сообщений или завершение работы
4. Ввод текста сообщения с консоли (менее 20 символов)

## Реализация

### Receiver.cpp
**Основные функции:**
- Создание и управление бинарным файлом-очередью
- Инициализация механизмов синхронизации (мьютексы, семафоры)
- Запуск и управление процессами Sender
- Чтение сообщений из очереди с синхронизацией

### Sender.cpp
**Основные функции:**
- Подключение к существующему файлу-очереди
- Отправка сигналов готовности Receiver
- Запись сообщений в очередь с соблюдением синхронизации
- Обработка пользовательского ввода

### Вспомогательные функции (Functions.h/Functions.cpp)
- **Валидация данных:** проверка чисел, имен файлов, выборов пользователя
- **Управление синхронизацией:** создание/открытие мьютексов и семафоров
- **Функции ожидания:** работа с handles объектов синхронизации

## Механизмы синхронизации

### 1. Кольцевая очередь FIFO
- Сообщения хранятся в бинарном файле как массив фиксированных блоков
- Используются отдельные файлы для позиций чтения и записи (`.pos`, `.readpos`)
- Циклическое использование буфера для эффективного управления памятью

### 2. Мьютексы (Mutexes)
- `MyMutex` - общий мьютекс для доступа к файлу
- `MyPositionMutex` - мьютекс для синхронизации позиций чтения/записи

### 3. Семафоры (Semaphores)
- `MyNotesAmountSemaphore` - счетчик доступных сообщений для чтения
- `MyNotNotesAmountSemaphore` - счетчик свободного места для записи

### 4. События (Events)
- `MyStartEventN` - события для синхронизации запуска процессов

## Алгоритм работы очереди

### Структура данных:
- Каждое сообщение занимает ровно 20 байт
- Файл представляет собой массив сообщений
- Отдельные файлы хранят текущие позиции чтения и записи

### Процесс записи (Sender):
1. Ожидание свободного места (`hNotNotesAmountSemaphore`)
2. Захват мьютекса доступа к файлу (`hMutex`)
3. Захват мьютекса позиции записи (`hPositionMutex`)
4. Чтение текущей позиции записи из файла `.pos`
5. Запись сообщения в соответствующую позицию
6. Обновление позиции записи
7. Освобождение ресурсов и увеличение счетчика сообщений

### Процесс чтения (Receiver):
1. Ожидание доступных сообщений (`hNotesAmountSemaphore`)
2. Захват мьютекса доступа к файлу (`hMutex`)
3. Захват мьютекса позиции чтения (`hPositionMutex`)
4. Чтение текущей позиции чтения из файла `.readpos`
5. Чтение сообщения из соответствующей позиции
6. Очистка прочитанной позиции
7. Обновление позиции чтения
8. Освобождение ресурсов и увеличение счетчика свободного места

## Особенности реализации

### Безопасность:
1. **Валидация ввода:** Все пользовательские данные проверяются регулярными выражениями
2. **Обработка ошибок:** Проверка возвращаемых значений системных функций
3. **Корректное завершение:** Освобождение всех системных ресурсов

### Синхронизация:
1. **Избежание deadlock:** Строгий порядок захвата мьютексов
2. **Эффективное ожидание:** Использование семафоров вместо активного ожидания
3. **Согласованность данных:** Гарантия целостности позиций чтения/записи

### Управление процессами:
1. **Автоматический запуск:** Receiver создает процессы Sender через `CreateProcess`
2. **Синхронизация запуска:** Использование событий для гарантии готовности всех процессов
3. **Передача параметров:** Имя файла и параметры передаются через командную строку

## Требования к системе

- **Операционная система:** Windows (используются Windows API функции)
- **Компилятор:** Поддерживающий C++11 или выше
- **Библиотеки:** Стандартная библиотека C++, Windows API

## Примечания

1. **Максимальная длина сообщения:** 20 символов (включая завершающий нуль)
2. **Кольцевой буфер:** При переполнении очередь начинает перезаписываться с начала
3. **Многопроцессность:** Поддерживается несколько независимых процессов Sender
4. **Синхронизация файлов:** Использование мьютексов предотвращает конфликты доступа
5. **Отказоустойчивость:** Программа корректно обрабатывает некорректный ввод и системные ошибки

## Преимущества реализации

1. **Масштабируемость:** Легко увеличить количество процессов Sender
2. **Надежность:** Гарантированная доставка сообщений через файловую систему
3. **Простота отладки:** Состояние очереди можно проверить через бинарный файл
4. **Эффективность:** Минимальные накладные расходы на синхронизацию
