# Лабораторная работа №5: Обмен данными по именованным каналам

Этот проект реализует клиент-серверную систему для управления параллельным доступом к файлу с записями о сотрудниках с использованием именованных каналов Windows. Система решает классическую задачу "Читатели-Писатели" (Readers-Writers Problem), обеспечивая корректный доступ к данным в многопроцессной среде.

## Особенности проекта

*   **Клиент-серверная архитектура:** Использует именованные каналы Windows (Named Pipes) для межпроцессного взаимодействия.
*   **Две версии реализации:**
    *   **Версия 1.0 (Server.cpp, Client.cpp):** Использует низкоуровневые Windows API примитивы синхронизации (мьютексы, семафоры).
    *   **Версия 2.0 (Server-20.cpp, Client-20.cpp):** Использует высокоуровневые C++ стандартные примитивы (`std::mutex`, `std::condition_variable`).
*   **Синхронизация доступа:** Реализует механизм блокировок на уровне записей:
    *   **Несколько клиентов могут одновременно читать одну и ту же запись.**
    *   **Модификация записи требует эксклюзивного доступа,** блокируя других читателей и писателей.
*   **Работа с бинарными файлами:** Данные сотрудников хранятся в бинарном файле со структурой `Employee`.
*   **Автоматическое управление клиентами:** Сервер сам создает указанное количество процессов-клиентов.
*   **Логирование операций:** Клиент записывает историю своих действий в файл `clientLogging.txt`.
*   **Модульные тесты:** Включает набор тестов для проверки функций ввода данных и структуры `Employee` (с использованием Google Test).

## Требования

*   **Операционная система:** Windows (используется Windows API, `<windows.h>`).
*   **Компилятор:** C++17 или новее (рекомендуется MSVC).
*   **Система сборки:** CMake 3.14+.
*   **Библиотека для тестов:** Google Test (gtest) — автоматически загружается через CMake.

## Принцип работы синхронизации

### Версия 1.0 (WinAPI)
Для каждой записи (сотрудника) сервер создает набор объектов синхронизации Windows API:
*   `writeSemafore` (семафор) — контролирует эксклюзивный доступ на запись (значение 1 = доступно).
*   `readMutex` (мьютекс) — защищает счетчик читателей.
*   `readerCount` — количество активных читателей записи.
*   `employeeDataMutex` (мьютекс) — защищает непосредственно данные записи в памяти.

**Алгоритм:**
*   **Чтение:** Первый читатель захватывает `writeSemafore`, последний — освобождает.
*   **Запись:** Писатель захватывает `writeSemafore`, блокируя других писателей и новых читателей.

### Версия 2.0 (C++ Standard)
Используется класс `ReadWriteLock`, реализующий алгоритм "писатели имеют приоритет" с использованием:
*   `std::mutex` для защиты данных
*   `std::condition_variable` для эффективного ожидания
*   Счетчики читателей и писателей

## Тестирование
Тесты проверяют граничные случаи, валидацию ввода и корректность операторов сравнения и потокового ввода/вывода для `Employee`.

## Примечания

*   **Имя именованного канала** зафиксировано как `\\.\pipe\pipe_name`.
*   **Имя сотрудника** ограничено 9 символами (с учетом завершающего нуля).
*   **Логирование:** 
*   **Уникальность ID:** Сервер гарантирует уникальность ID сотрудников при создании файла.
*   **Совместимость версий:** Клиент и сервер должны быть одной версии (1.0 с 1.0, 2.0 с 2.0).
